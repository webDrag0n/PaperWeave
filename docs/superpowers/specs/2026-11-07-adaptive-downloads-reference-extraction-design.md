# 自适应并行下载、统一进度与 PDF 引用提取增强设计

日期：2026-11-07
状态：按现有需求实施

## 1. 目标与范围

本次改造覆盖三条现有链路：

1. 导入弹窗中的多 URL 下载和本地多文件导入。
2. 阅读器中的单篇／全部引用下载，以及下载后的自动引用关系抓取。
3. 阅读器引用页和 3D 图谱节点侧栏的实时进度展示。

采用稳健自适应策略：下载调度器初始并发为 3，根据延迟、超时、HTTP 429、服务端错误和普通失败在 1–6 之间调整。Semantic Scholar 等已有专用限流的数据源继续服从各自的节流和退避规则，不因下载并发提高而放大请求量。

不实现递归引用下载：新论文入库后自动抓取其引用与被引关系，但不会继续自动下载新发现的未入库文献。

## 2. 方案选择

采用主进程统一自适应调度器。仅在前端使用 `Promise.all` 无法覆盖 Agent API，也难以统一处理任务去重、进度聚合与存储竞态；固定线程池则不能根据网络变化调整。

调度器负责执行通用异步任务，业务服务仍负责 URL 规范化、PDF 导入、去重、建边和外部引用移除。浏览器预览模式复用同一调度算法，但保留其既有跨域限制。

## 3. 组件设计

### 3.1 自适应任务调度器

新增独立调度模块，提供批量任务执行和任务事件回调：

- 全局并发初始值为 3，允许范围为 1–6；同一主机设置独立上限，避免单站拖慢全部任务。
- 连续成功且延迟稳定时逐步增加并发；出现超时、429 或连续服务端错误时立即降低并进入短暂冷却。
- 429 优先遵守 `Retry-After`，网络错误采用有上限的指数退避；不可重试的内容错误直接计入失败。
- 任务按完成数推进批次进度，单项失败不会阻塞后续任务。
- 相同规范化 URL、arXiv ID 或同一论文的引用 key 不重复执行。
- PDF 元数据提取完成后、注册新论文前再次检查内容哈希，消除并行导入相同内容时的竞态。

进度事件在原有字段上增加可选的 `active`、`pending`、`concurrency`、`failed` 和 `operationId`，旧调用方可以忽略这些字段。批量聚合器统一发出进度，避免并发子任务各自覆盖总数和当前计数。

### 3.2 批量导入与引用下载

主服务增加多 URL 导入入口，桌面 IPC 一次提交整批链接；现有单 URL 接口保持兼容。导入弹窗显示每条 URL 的状态，并显示批次汇总与当前并发。

`downloadAllRefs` 改为通过调度器执行现有单篇下载逻辑，保留 `downloaded / skipped / failed` 返回结构。每篇成功入库的新论文仍进入自动引用抓取队列；队列对等待中和运行中的论文 ID 同时去重。

自动抓取采用后台任务，不阻塞批量下载完成。不同论文的进度按 `paperId` 分开保存和推送，Semantic Scholar 请求继续通过现有限流队列。

### 3.3 阅读器与 3D 图谱进度

提取可复用的进度渲染逻辑，阅读器引用页和图谱节点侧栏分别拥有进度容器。

- 阅读器保留现有抓取／下载按钮忙碌状态和完成后延迟隐藏行为。
- 图谱侧栏在“它引用的／引用它的”区域之前展示当前节点任务阶段、完成数、总数、当前条目和并发信息。
- 渲染进程进度事件同时路由到阅读器与图谱；只有当前打开论文或当前选中节点匹配时才更新对应区域。
- 手动点击抓取时立即显示定位阶段；后台自动抓取和 Agent API 触发的事件使用同一展示路径。
- 多论文并发任务不共享一个计数器，切换节点时显示该节点最近一次仍在有效期内的进度。

### 3.4 PDF 参考文献提取

修复 `extractRefText` 的页序和接受条件：

- 以页码为键缓存提取文本，每次扩窗后按页码升序拼接，不再按扩窗顺序追加。
- 清理重复页眉、页脚和孤立页码，修复跨行断词，但保留条目边界所需的换行。
- `References`、`Bibliography` 等短标题继续作为入口；参考文献之后出现附录、补充材料等短标题时截断。
- 同时接受编号与无编号参考文献。无编号条目结合作者起始行、年份、DOI／arXiv／URL 和条目结束标点切分，支持机构作者与名在前、姓在后的格式。
- 标题提取沿用 DOI／arXiv 优先、结构化数据源与标题检索回退的在线识别链路；网页、软件和其他灰色文献无法可靠识别时保留为未解析项，不生成虚假元数据。

## 4. 数据流

### 批量下载

1. GUI 或现有服务提交任务，调度器去重并启动初始并发。
2. 每个任务完成地址解析、PDF 下载、元数据与参考文献提取、哈希复核和入库。
3. 聚合器按已完成数推送批次进度，网络反馈驱动后续并发调整。
4. 新论文进入自动引用抓取队列，批量下载先返回汇总，后台继续补全关系。

### 引用抓取进度

1. 主进程按论文 ID 保存并节流推送阶段事件。
2. 阅读器和图谱分别接收匹配当前论文的事件。
3. 图谱重新选中节点时，根据内存中的最近进度立即恢复展示。
4. 完成事件短暂保留后隐藏，失败事件保留可读原因。

## 5. 异常与边界

- 重复任务返回已有任务结果，不重复写文件或建边。
- 相同内容经不同 URL 同时到达时，最终哈希复核只保留一个论文记录。
- 无开放获取 PDF、非 PDF 响应和解析失败按单条失败汇总，其他任务继续。
- 抓取期间切换视图不取消任务；进度事件不会误显示在其他论文上。
- 本地文件批量导入保持现有冲突确认流程；并行仅用于可独立处理的导入任务。
- 浏览器预览仍受跨域和存储能力限制，不承诺与桌面端相同的外部站点可达性。

## 6. 验收与测试

1. 调度器单元测试覆盖并发上限、成功升档、429／超时降档、冷却、任务去重、失败不阻塞和完成计数。
2. 批量引用下载测试覆盖聚合进度、重复内容、单条失败与自动抓取只触发一次。
3. 阅读器和 3D 图谱分别验证手动及后台抓取进度、节点切换隔离和完成隐藏。
4. 以 `https://arxiv.org/pdf/2603.01966` 为真实回归样本：38 页，参考文献位于第 11–13 页，应提取 37 条无编号条目，并验证其中的 arXiv 条目可进入在线识别流程。
5. 增加小型合成文本夹具，覆盖页序、无编号条目、机构作者、附录截断和跨行断词，避免常规测试依赖网络。
6. 更新 Agent 接口文档及受影响的 API／MCP 测试，运行完整 `selftest`、`apitest`、`mcptest` 和引用索引回归。
