# 设计记录

本目录保存较大功能在开发前写下的设计说明与实施计划。它们是**历史记录**：描述的是动笔时的意图与方案，实现过程中的调整不会回写到这里。当前行为以代码和 [架构与设计](../architecture.md) 为准。

- `specs/`：设计说明。回答要解决什么问题、选了哪个方案、为什么不选其他方案、边界情况如何处理。
- `plans/`：实施计划。把设计拆成可逐项执行与验证的任务，供 coding agent 或开发者按步骤完成。

目录名与文件格式来自 agent 工作流工具 superpowers 的默认约定，文件名为 `YYYY-MM-DD-<主题>[-design].md`。

## 何时需要写设计记录

满足任一条件时，先写设计说明并在 Issue 或 PR 中达成一致，再开始实现：

- 新增或改变持久化数据结构。
- 改变 Agent 接口契约的既有行为。
- 涉及鉴权、配对或网络暴露面。
- 跨越主进程、渲染进程与外部客户端中的两个以上部分。
- 引入新的运行时依赖。

小范围的缺陷修复和界面调整不需要设计记录，在 PR 描述中说明即可。新增记录后在上面的索引表中追加一行。
